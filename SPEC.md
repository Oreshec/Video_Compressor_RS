## 1. Цель проекта

Разработать кроссплатформенное настольное приложение для сжатия видео до заданного размера файла с максимально возможным сохранением воспринимаемого качества.

Приложение должно предоставлять два режима работы:

- **Простой режим** — минимальное количество элементов управления, автоматический подбор параметров.
- **Расширенный режим** — полный контроль над кодеками, разрешением, FPS, аудио, параметрами энкодера и другими настройками.

Основной принцип продукта: пользователь задаёт желаемый результат, приложение самостоятельно выбирает подходящие параметры кодирования.

### 1.1. Приоритеты

1. Соблюдение максимального размера итогового файла.
2. Максимально возможное визуальное качество в пределах установленного лимита.
3. Сохранение приемлемой плавности движения.
4. Сохранение аудио, субтитров и дополнительных дорожек, если это совместимо с выбранными настройками.
5. Предсказуемость поведения и прозрачное информирование об ограничениях.
6. Удобство пакетной обработки файлов.

Приложение не должно обещать отсутствие потери качества при перекодировании.

### 1.2. Лицензионная модель (решено)

Приложение распространяется как open-source под **GNU GPLv3**. Следствия:

- Slint используется по лицензии **GNU GPLv3**; собственные файлы проекта— MIT/Apache-2.0 не требуются, но допустимы.
- Допустима поставка **GPL-сборки FFmpeg** с libx264/libx265/libvmaf; при этом соблюдаются стандартные GPL-обязательства: тексты лицензий в комплекте, ссылки на исходники, атрибуция в диалоге «О программе».
- Приложение не имеет обязательств по закрытию исходного кода поставляемых сборок — наоборот: репозиторий открыт.

## 2. Технологический стек

### 2.1. Основные технологии

- Rust — бизнес-логика, управление задачами, файловые операции и интеграция с медиадвижком.
- Slint — интерфейс пользователя.
- FFmpeg / FFprobe — анализ медиафайлов, кодирование, обработка потоков и проверка результата.
- Система хранения настроек и истории — локальная (JSON/SQLite — решение на этапе архитектуры), без обязательного подключения к сети.

### 2.2. Архитектурные принципы

Код следует SOLID там, где применимо. Репозиторий — Cargo workspace:

- крейт `vc-core` — логические компоненты без UI-зависимостей, полностью тестируемый unit-тестами;
- крейт приложения — QueueManager, ProfileManager, репозитории, UI на Slint.

Логические компоненты:

- `Application` — запуск, конфигурация и жизненный цикл приложения.
- `UI` — отображение интерфейса и обработка пользовательских действий.
- `MediaProbe` — анализ исходных файлов.
- `EncodingPlanner` — расчёт параметров сжатия.
- `Encoder` — выполнение кодирования через выбранный энкодер.
- `QueueManager` — очередь задач, отмена, пауза и восстановление.
- `ProfileManager` — создание, редактирование и применение профилей.
- `SettingsRepository` — хранение настроек.
- `HistoryRepository` — история обработки.
- `OutputValidator` — проверка готовых файлов.
- `HardwareDetector` — обнаружение доступных энкодеров и оборудования.

Это логические границы ответственности, не требование отдельного крейта на каждый компонент.

UI не должен напрямую управлять процессами FFmpeg или содержать алгоритм подбора параметров.

Совместимый код из текущей версии переносится: `probe.rs`, `bitrate.rs`, `encode.rs` (прогресс через `-progress pipe:1`, отмена, повторные попытки, фолбэк на CPU, 2-pass), `ffmpeg.rs`, `presets.rs` и 16 существующих тестов. GUI-слой на egui не переносится.

### 2.3. Slint-специфика

- Drag-and-drop **файлов из ОС** — очень свежий API (появился в Slint 1.17, поддержка файлов добавлена в сентябре 2026). На Этапе 1 обязательно прототипировать; фолбэк — системные диалоги через `rfd` — входит в критерии приёмки в любом случае.
- Нативных диалогов выбора файлов/папок в Slint нет: работать из Rust-стороны через `rfd`.
- Локализация: `@tr()` + gettext `.po` — закладывается с первого дня, чтобы «Язык» в настройках (§10) не превратился в ретрофит.
- Шрифты: кроссплатформенно — либо встраиваемый шрифт с кириллицей (Inter/Noto Sans), либо загрузка системного через fontconfig (Linux); не повторять Windows-хардкод путей из текущей версии.

## 5. Режимы работы

### 5.1. Простой режим

Видимые настройки:

- Целевой максимальный размер.
- Профиль обработки.
- Основные параметры в сворачиваемой панели.
- Запуск и управление очередью.

Профили:

**Качество**
- Приоритет визуального качества; допускается более длительная обработка.
- Максимальное качество в рамках целевого размера и ограничений.

**Баланс**
- Компромисс между качеством и скоростью.

**Скорость**
- Приоритет скорости кодирования при обязательном соблюдении лимита размера.

Профили не подменяют целевой размер. Все три профиля обязаны соблюдать установленный лимит. Бюджет времени привязан к профилю: «Скорость» — жёсткий бюджет; «Качество» — бюджета нет, действует только лимит попыток (§7.7).

### 5.2. Основные параметры

Сворачиваемая панель:

- Контейнер.
- Видеокодек.
- Разрешение: автоматическое или ручное.
- При необходимости — выбор аудиопрофиля.

Список вариантов зависит от возможностей энкодера и матрицы совместимости (§6.5).

### 5.3. Расширенный режим

Единая страница со сворачиваемыми группами:

**Видео**
- Кодек. Разрешение. Частота кадров. Пропорции. Параметры качества.

**Кодирование**
- Автоматический / аппаратный / программный энкодер.
- Конкретный доступный энкодер.
- Скоростной пресет. Rate control. Количество проходов.
- GOP, B-frames и прочие поддерживаемые параметры.

**Аудио**
- Кодек. Битрейт. Частота дискретизации. Выбор дорожек.
- Сохранение совместимых дорожек без перекодирования.

**Субтитры и дополнительные потоки**
- Выбор дорожек. Сохранение совместимых потоков.
- Предупреждение о несовместимости.

**Вывод**
- Контейнер. Папка сохранения. Шаблон имени файла. Поведение при конфликте имён.

Правило отображения (снимает противоречие v0.1):
- **Скрыты** — неподдерживаемые экземпляры (например, кодеки, отсутствующие в сборке FFmpeg);
- **Показаны серым с пояснением** — функции, недоступные в текущей конфигурации, но поддерживаемые в принципе (например, 2-pass для аппаратного энкодера).

### 5.4. Приоритет настроек

Уровни, от низшего к высшему:

1. Значения по умолчанию профиля.
2. Настройки очереди.
3. Индивидуальные переопределения файла.

Сброс индивидуального переопределения возвращает файл к уровню 2. Посадка в UI обязана отражать, с какого уровня взято значение.

## 6. Контейнеры и кодеки

### 6.1. Контейнеры

- **MP4** — формат по умолчанию.
- **MKV** — рекомендуемый для расширенного режима (единственный из набора, где субтитры ASS/SSA/PGS/SRT и несколько аудиодорожек сохраняются без принудительной конверсии; просто закрывает требования §6.4).
- **MOV** — дополнительный.
- **WebM** — дополнительный (только VP8/VP9/AV1 + Opus/Vorbis — см. матрицу).
- ~~AVI~~ — **исключён**: H.264 в AVI конфликтует с B-frames, AAC в AVI не поддерживается штатными плеерами; контейнер систематически нарушает приоритеты 1–2.

Контейнер и видеокодек выбираются независимо, с автоматической проверкой совместимости по §6.5. Программа не считает контейнер причиной повышения качества или эффективности сжатия.

### 6.2. Видеокодеки

Приоритет реализации:

- H.264 — базовый вариант.
- H.265 / HEVC — дополнительный.
- AV1 — при наличии подходящего энкодера (libsvtav1 присутствует в большинстве сборок; кодирование заметно медленнее).
- VP9 — для WebM при доступном энкодере.

Фактический перечень зависит от поставляемой сборки FFmpeg и оборудования. Состав кодеков строится от лицензии: libx264 и libx265 требуют GPL-сборки FFmpeg — это приемлемо (§1.2); libsvtav1/libvpx нейтральны.

### 6.3. Аудио

- AAC — основной вариант для MP4.
- Сохранение совместимого аудио без перекодирования (копирование, если кодек контейнеро-совместим и укладывается в бюджет).
- Автоматический выбор разумного битрейта в простом режиме; ручное управление в расширенном.
- Несколько аудиодорожек — если поддерживается комбинацией контейнера и кодеков (полная поддержка — MKV).
- При несовместимости — предупреждение до запуска.

### 6.4. Субтитры

- Сохранять поддерживаемые текстовые (и прочие поддерживаемые) субтитры.
- В MP4 — конвертация текстовых в `mov_text`; PGS/VobSub несовместимы — предупреждение и предложение перейти на MKV.
- В MKV — сохранение как есть.
- Если формат не поддерживает исходный тип субтитров — предупреждение и совместимая альтернатива. Дорожки не удаляются молча.

### 6.5. Матрица совместимости (новое)

Совместимость контейнер × кодек × аудио × субтитры — **декларативные данные** (единая таблица в `vc-core`), а не разрозненные проверки в коде. Потребители:

- UI — фильтрация доступных вариантов;
- EncodingPlanner — валидация плана до запуска;
- OutputValidator — проверка результата против ожидаемой структуры.

Минимальное содержимое: для каждой пары «контейнер–кодек» — допустимые аудиокодеки, поддерживаемые типы субтитров, поддержка faststart, примечания (например: WebM принимает только VP8/VP9/AV1 и Opus/Vorbis; MP4 — субтитры только mov_text).

## 7. Алгоритм сжатия

### 7.1. Основной принцип

Пользователь задаёт максимальный размер файла. Программа подбирает параметры для наилучшего качества в заданных пределах.

Размер — обязательное ограничение. Качество — оптимизируемая характеристика с настраиваемым минимальным порогом.

### 7.2. Этапы обработки

1. Проверить существование, доступность и читаемость исходного файла.
2. Получить длительность, разрешение, FPS, сведения об аудио, субтитрах и других потоках; зафиксировать нестандартные свойства источника (§7.9).
3. Рассчитать бюджет размера для видео, аудио и накладных расходов (§7.3).
4. Определить совместимые кодеки и доступные энкодеры (по матрице §6.5).
5. Рассчитать начальный набор параметров.
6. Выбрать разрешение и частоту кадров (§7.4–7.5).
7. Выполнить пробное кодирование или основной проход в зависимости от алгоритма.
8. При необходимости — дополнительные проходы/итерации.
9. Проверить итоговый файл (OutputValidator, §7.10).
10. При превышении лимита — скорректировать параметры и повторить в рамках политики качества.
11. Переместить проверенный результат в конечное место назначения.
12. Записать результат в историю.

### 7.3. Целевой размер

Параметр `max_output_size_bytes`. Все внутренние расчёты — **в байтах** (!int; интерфейс отображает МБ/ГБ).

Программа учитывает накладные расходы контейнера: оценка ~1–2 % от битрейтового бюджета плюс явный запас относительно лимита (коэффициент безопасности — настраиваемая константа планировщика, стартовое значение наследуется от текущей версии).

Успешный результат: `actual_output_size_bytes <= max_output_size_bytes`. Точность попадания в желаемый размер вторична по отношению к соблюдению максимума.

### 7.4. Автоматический подбор разрешения

- Сохранять пропорции исходного изображения.
- Не увеличивать исходное разрешение.
- При ограниченном битрейте оценивать целесообразность уменьшения (лестница высот; критерий — биты на пиксель).
- Не уменьшать разрешение без причины.
- Ручное разрешение в расширенном режиме не меняется автоматически без явного согласия.
- Расчёт bpp учитывает **отображаемые** размеры кадра (после авто-поворота, §7.9) и частоту кадров.
- Коэффициенты bpp — на кодек (H.264/HEVC/AV1/VP9 по-разному эффективны): параметр хранится per-codec с самого начала, чтобы избежать перекалибровки лестницы при добавлении кодеков.

### 7.5. Автоматический подбор FPS

- Сохранять исходную частоту кадров, если лимит позволяет.
- Для источников выше 30 FPS — 30 FPS как предпочтительный вариант экономии.
- Не повышать 24 FPS до 30.
- Снижение ниже 30 FPS в простом режиме — только при экстремально жёстком лимите и с предупреждением.
- 24 FPS — нижняя ступень автоподбора в рамках политики качества.
- В расширенном режиме — ручной контроль.
- Снижение FPS не заменяет уменьшение разрешения; выбор зависит от характера движения.

### 7.6. Автоматический выбор энкодера

- По умолчанию — автоматический с предпочтением подходящего аппаратного энкодера.
- Аппаратное кодирование при доступности; программное — альтернатива; ручной выбор в расширенном режиме.
- Профиль «Качество» не переключает автоматически на CPU: решение зависит от возможностей энкодера, кодека, целевого размера и ограничений.
- Поддержка выбранного кодека и параметров проверяется до запуска (HardwareDetector + матрица §6.5).

### 7.7. Итерации и остановка

- Ограниченное количество попыток (стартовое значение — как в текущей версии).
- Ограничение времени/ресурсов — по бюджету профиля (§5.1).
- Определённые критерии остановки.
- Проверка фактического размера после каждого варианта.
- Обработка ошибок энкодера; фолбэк с аппаратного на программный.
- Очистка временных файлов после завершения или отмены.

Бесконечное повторное кодирование не допускается.

### 7.8. Оценка качества

Метрики — **опциональны и ограничены по стоимости**: прогон метрики требует полного декодирования исходника и результата (сопоставимо с самим кодированием по времени чтения).

- **SSIM** — основной, дешёвый фолбэк.
- **VMAF** — при наличии libvmaf в сборке FFmpeg.
- По умолчанию метрики **выключены**; включаются для профиля «Качество» и/или начиная со 2-й итерации.
- Пороговые значения: «Качество» — VMAF ≥ 80, «Баланс» — VMAF ≥ 70 (при недоступности VMAF — эквивалент SSIM/bpp; точные значения калибруются на Этапе 3).
- Метрики не гарантируют полного совпадения с субъективным восприятием — в UI это оговаривается.
- Если минимальный порог качества невозможно соблюсти вместе с размером: одна корректирующая итерация (понижение разрешения/FPS по лестнице) + явное предупреждение; «вечная коррекция» запрещена.

В простом режиме ограничение качества сохраняется с предупреждением о невозможности. В расширенном режиме порог можно явно отключить.

### 7.9. Нестандартные свойства источника (новое)

MediaProbe обязан детектировать и сохранять в MediaInfo:

1. **VFR** (переменная частота кадров): `avg_frame_rate` ≠ `r_frame_rate`. Для расчёта bpp используется `avg_frame_rate`; решение о-normalization FPS — по §7.5 с явным выбором `-fps_mode`.
2. **Ротация (display matrix)**: FFmpeg при кодировании авто-поворачивает кадр. Планировщик считает «видимое» разрешение (у вертикального видео с телефона 1920×1080 фактический кадр — 1080×1920) и от него считает bpp и лестницу.
3. **Чередование (interlace)**: `field_order`. Политика: сохранить флаг чередования либо деинтерлейс — с явным выбором и предупреждением в расширенном режиме.
4. **10-bit / HDR**: сейчасlocking `yuv420p` 8-bit неверно для таких источников. Минимум: детект + выбор «понизить с предупреждением» или «сохранить 10-bit» для HEVC/AV1/VP9. HDR tone mapping — вне рамок v1, источник помечается предупреждением.
5. `default_output_path`: расширение выхода определяется выбранной комбинацией контейнера и кодека (§6.5), а не расширением входа.

### 7.10. OutputValidator (новое)

Проверка результата до перемещения в конечное расположение:

- ffprobe результата успешен.
- Длительность ≈ исходной (допустимое отклонение — константа, стартово ±1 с).
- Ожидаемые аудио-/субтитровые дорожки присутствуют (см. план).
- `actual_size_bytes <= max_output_size_bytes`.
- Файл декодируем: ffprobe-сканирование битрейтов (быстрое, без полного декодирования).

Провал любого пункта → результат не считается успешным; запускается корректирующая итерация или ошибка (§11.3).

## 8. Аппаратное и программное кодирование

### 8.1. Общие требования

- Обнаружение доступных энкодеров при первом запуске или по запросу.
- Отсутствие предположений о наличии NVIDIA, AMD, Intel — поддерживаются доступные варианты в пределах сборки и ОС.
- Поддержка выбранного кодека и параметров проверяется до запуска.
- Фолбэк с аппаратного энкодера на программный при сбое (переносится из текущей версии).

### 8.2. Отображение в интерфейсе

Простой режим: автоматический выбор.

Расширенный режим: автоматический; аппаратное кодирование; программное; конкретный энкодер из доступных.

Если аппаратное кодирование недоступно — предлагается программный вариант и сообщается причина (если определена).

## 9. Пакетная обработка

### 9.1. Настройки очереди

- Общий профиль обработки; общие настройки по умолчанию; индивидуальные переопределения файлов (приоритет — §5.4).
- Создание, редактирование, копирование, удаление пользовательских профилей.
- Применение профиля ко всей очереди или выбранным файлам.
- Визуальное обозначение индивидуальных изменений.
- Создание профиля и применение профиля — разные действия.

### 9.2. Управление задачами

Состояния: в очереди; анализ; подготовка; кодирование; проверка результата; успешно; ошибка; отменено; **приостановлено**.

Уточнение по паузе: возможна только **между задачами** (внутри кодирования процесс ffmpeg возобновляемо не останавливается; экзотическое возобновление через pass-логи 2-pass — не поддерживается и не планируется в v1).

- Отмена задачи и удаление ожидающих задач из очереди — поддержаны.
- Параллельная обработка настраиваемая; по умолчанию — последовательное кодирование (предсказуемый расход ресурсов). Анализ (probe) файлов может выполняться параллельно всегда.

### 9.3. Восстановление очереди

После перезапуска восстанавливаются: настройки, история, состояние очереди, индивидуальные параметры файлов.

- Незавершённое кодирование не считается успешным: соответствующие задачи получают статус «требует повторного запуска».
- Перед повторным запуском — проверка исходников (probe), временных файлов и целевого расположения.
- Состояние очереди и настройки записываются атомарно (см. §10).

## 10. Настройки приложения

Отдельный экран настроек.

**Общие**
- Язык (реализация — `@tr()` + gettext, §2.3).
- Поведение при запуске. Восстановление последней сессии. Уведомления.

**Обработка**
- Папка по умолчанию. Шаблон имени файла. Поведение при конфликте имён.
- Очистка временных файлов. Количество параллельных задач. Поведение после завершения.

**История**
- Хранение истории. Очистка истории. Открытие папки результата.

**Производительность**
- Автоматический или ручной выбор энкодера.
- Ограничения параллельной обработки. Диагностика доступных энкодеров.

**Безопасность файлов**
- Автоматическое удаление исходников по умолчанию **выключено**.
- Включение требует явного согласия пользователя (отдельный диалог).
- Удаление исходника — только после подтверждения успеха OutputValidator (§7.10).

**Надёжность хранения** (новое)
- Все файлы состояния (настройки, очередь, история) записываются атомарно: запись во временный файл + rename (как в current-версии надо добавлять), чтобы обрыв питания не оставлял повреждённый JSON. Повреждённый файл → значения по умолчанию + запись в лог, не крах.

## 11. Выходные файлы и ошибки

### 11.1. Сохранение результата

- Сохранение рядом с оригиналом; выбор другой папки; шаблоны имён.
- Защита от случайной перезаписи: при существующем файле — суффикс `(2)` и т.п. или запрос пользователя (поведение — настройка §10).
- Открытие папки результата. Повторная обработка с другими настройками.

### 11.2. Временные файлы

- Кодирование — во временный файл.
- Итоговый файл становится доступен в конечном расположении только после успешного завершения и проверки OutputValidator (§7.10).
- При ошибке существующий пользовательский файл не подменяется частичным результатом.

### 11.3. Ошибки

Понятные сообщения для случаев:

- Неподдерживаемый формат.
- Повреждённый исходник.
- Недостаток свободного места (реальная проверка свободного места до запуска: ожидаемый размер + место под временные файлы и pass-логи).
- Недоступный энкодер.
- Несовместимость контейнера и кодека (по матрице §6.5 — до запуска).
- Ошибка кодирования.
- Превышение лимита.
- Невозможность соблюсти минимальный порог качества.
- Ошибка записи результата.

Технические подробности FFmpeg — в диагностическом журнале, но не подменяют понятное сообщение.

## 14. Критерии приёмки

1. Запускается на поддерживаемых версиях Windows и Linux.
2. Добавление видео: диалог выбора, множественный выбор, папка, drag-and-drop (при недоступности dnd-прототипа — как минимум диалоги).
3. Указание максимального размера результата (внутренне — байтах).
4. Простой режим не требует ручного выбора кодека и энкодера.
5. Расширенный режим даёт доступ ко поддерживаемым параметрам.
6. При совместимой конфигурации результат не превышает заданный размер.
7. При невозможности соблюсти одновременно размер и порог качества — предупреждение.
8. Автоподбор не превышает заданное количество итераций.
9. Несовместимые контейнеры, кодеки и потоки выявляются до обработки, где возможно на этапе анализа (по матрице §6.5).
10. Ошибка одного файла не прерывает всю очередь.
11. Индивидуальные переопределения отличаются от унаследованных; уровень виден (§5.4).
12. История и настройки сохраняются между запусками.
13. Восстановление очереди: «запущено 3 файла → процесс убит на 2-м → после перезапуска 1-й — „успешно“, 2-й — „требует повторного запуска“, 3-й — „в очереди“».
14. Отмена обработки не подменяет исходный или существующий пользовательский файл частичным результатом.
15. Интерфейс остаётся отзывчивым во время анализа и кодирования.
16. Автоматическое удаление исходников выключено по умолчанию.
17. Пользовательские профили: создание, редактирование, применение.
18. При недоступности аппаратного энкодера используется альтернативный программный вариант.
19. Прототип UI-отзывчивости: перерисовки интерфейса при активном кодировании не имеют ощутимых фризов; долгих блокирующих операций на UI-потоке нет.
20. Производительность: ffprobe-анализ файла ~5 ГБ — ≤ 2 с, асинхронно.
21. Память процесса приложения при активном кодировании ≤ 400 МБ без учёта дочерних процессов ffmpeg.
22. Атомарность состояния: прерывание записи settings/очереди не оставляет повреждённый файл, приложение действует по §10.
23. Планировщик (§7) покрыт unit-тестами без FFmpeg; дополнительно — smoke-тесты с реальным ffmpeg (как в текущей версии).
